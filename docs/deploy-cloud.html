Hosting options

Picking a host that actually fits

Where to run a self-hosted instance when you do not want to keep a server yourself. Strata has three requirements that rule out most modern hosting platforms, and understanding them takes two minutes and saves a wasted afternoon, so they come first.

This is still self-hosting

Renting the machine does not change who owns the instance or the data: you deploy it, you configure it, you upgrade it. If you want a version somebody else runs, that is Strata Cloud.

What Strata needs from a host

  1. A disk that stays put

    STRATA_DATA_DIR holds accounts, the session signing secret, encrypted credentials, the delivery log and the audit log. If the disk resets, everyone is signed out and all of that is gone.

    The models survive regardless, because they live in git. That is the one thing you never have to worry about.

  2. Exactly one instance

    The workspace is a git working tree. Two containers writing to it will corrupt it. Any platform that autoscales by default needs to be pinned to one instance, and if it cannot be pinned, it cannot run strata.

  3. Long lived connections

    The UI holds a stream open for presence and live updates. Platforms with short response timeouts, or proxies that buffer, break that feature in a way that looks like a bug rather than a configuration problem.

The short answer

Serverless is a poor fit. Strata is a small container that wants a small disk and wants to stay running. A cheap VM or a container platform with a volume is what it is built for.

The honest conclusion

Render is the only host on this list that runs a container, needs no credit card, and is free indefinitely. Everything else either wants a card, has no free tier for new accounts, or cannot keep a container running.

And every free container tier sleeps. That is the business model, not an oversight. There is no free always-on container host without a card, so the question is not which host avoids the cold start. It is what the visitor sees during it.

How to choose

  • You want strangers to try strata. Render free, or Cloud Run pinned to one instance. Nothing precious is stored, so losing it does not matter.
  • You want a real instance for your team, cheaply. Fly.io with a volume, or an Oracle Always Free VM.
  • You want something you will not have to think about. A small VPS running Docker Compose.

Walkthrough: Render

Render can run a published container directly, with no repository and no build. That makes it the shortest route to an instance you can reach from anywhere, and it is free to try.

  1. Create the service from the image

    In Render, choose New, then Web Service, then Existing image. There is nothing to connect and nothing to fork.

    Image URL

    ghcr.io/rk-chavali/strata:latest

    Pinned to the minor version so you get patches and never a surprise major upgrade.

  2. Generate a password hash for the administrator

    Do this before the first start. It is what stops a stranger becoming your administrator if the disk is ever lost. 

    docker run --rm -it ghcr.io/rk-chavali/strata   node apps/server/dist/hash-password.js

    It asks for a password without echoing it, then prints a hash like scrypt$a1b2...$c3d4.... The hash is safe to paste into a settings screen: it cannot be replayed anywhere else and it cannot be turned back into the password.

  3. Set the environment variables

    Under Environment. STRATA_MODEL_REPO is the repository holding your models, which Strata clones on first start because there is no host directory to mount. 

    STRATA_WORKSPACE      /workspace
STRATA_DATA_DIR       /data
STRATA_MODEL_REPO     https://github.com/your-org/data-models.git
STRATA_ADMIN_USERNAME admin
STRATA_ADMIN_PASSWORD_HASH  scrypt$a1b2...$c3d4...
STRATA_COOKIE_SECURE  true
STRATA_TRUST_PROXY    true
GITHUB_TOKEN          ghp_your_token_here

    STRATA_TRUST_PROXY matters here: Render terminates TLS in front of the container, so without it every visitor shares one sign-in throttle bucket.

  4. Set the health check path

    /api/health

    Render uses this to tell a slow start from a failed one, and to stop routing traffic to an instance that has stopped answering.

  5. Add a disk

    Mount it at /data, the value of STRATA_DATA_DIR above. That is where accounts and the session signing secret live.

    The free plan has no disks

    Without one, /data is wiped whenever the instance restarts, which signs everyone out and reopens first-run setup. Your models survive because they are in git, but anyone reaching the URL after a restart could claim the administrator account. Seeding the administrator above is what closes that. For anything real, use a paid plan and a disk.

  6. Keep it to one instance

    The git working tree is shared mutable state, so two containers writing one workspace will corrupt it. Free gives you one instance regardless. On a paid plan, set the instance count to 1 and leave it there.

Free instances sleep

After fifteen minutes of no traffic, and the next request waits about a minute while the container wakes. Fine for evaluation and for a team that uses it occasionally. Not fine as the tool somebody opens first thing every morning.

Walkthrough: a real instance on Fly.io

When you want an instance that keeps real models, this is the cheapest option that meets all three requirements properly.

  1. Create the app and a volume

    fly launch --no-deploy --name strata-yourteam
fly volumes create strata_data --size 3 --region lhr

    Three gigabytes is generous. The data directory is well under a megabyte, and the rest is the git checkout.

  2. Write the config

    fly.toml

    app = "strata-yourteam"
primary_region = "lhr"

[build]
  dockerfile = "Dockerfile"

[env]
  PORT = "4000"
  STRATA_DATA_DIR = "/data/auth"
  STRATA_WORKSPACE = "/data/workspace"
  STRATA_MODEL_REPO = "https://github.com/your-org/data-models.git"
  STRATA_COOKIE_SECURE = "true"
  STRATA_TRUST_PROXY = "true"

[[mounts]]
  source = "strata_data"
  destination = "/data"

[http_service]
  internal_port = 4000
  force_https = true
  # One machine, always. The git working tree cannot take two writers.
  auto_stop_machines = false
  auto_start_machines = false
  min_machines_running = 1

[[vm]]
  size = "shared-cpu-1x"
  memory = "512mb"

  3. Set the secrets

    fly secrets set \
  GITHUB_TOKEN=ghp_your_token_here \
  STRATA_ADMIN_USERNAME=admin \
  STRATA_ADMIN_PASSWORD_HASH='scrypt$a1b2...$c3d4...'

    Generate the hash first. See Seeding the administrator.

  4. Deploy

    fly deploy

    Then watch it come up:

    fly logs

    You want to see the repository clone and the administrator seeded, before the listening line.

  5. Check the volume is really mounted

    fly ssh console -C "ls -la /data"

    You should see auth and workspace. If /data is empty after a restart, the mount is not working and you are one deploy away from losing your accounts.

Turn off auto stop

Fly can stop machines when idle and start them on a request. That is a nice feature and it is wrong here: a cold start re-clones the repository, and a stopped machine cannot serve the event stream the UI is holding open. The settings above keep one machine running.

Free forever: an Oracle VM

If cost is the deciding factor and you do not mind managing a machine, Oracle's Always Free tier gives you a real ARM VM with a real disk that stays on. In June 2026 the ARM allowance was halved to 2 CPUs and 12 GB of memory, which is still far more than Strata needs.

  1. Create the instance

    An Ampere A1 shape with 1 CPU and 6 GB is plenty. Pick a recent Ubuntu image. Open port 443 in the security list.

  2. Install Docker

    sudo apt update && sudo apt install -y docker.io docker-compose-plugin git
sudo usermod -aG docker $USER

    Nothing to clone: the next step pulls a published image.

  3. Follow the Docker Compose walkthrough

    From here it is exactly the self-hosting walkthrough. Put Caddy or nginx in front for TLS, and set STRATA_COOKIE_SECURE=true and STRATA_TRUST_PROXY=true.

One caveat worth knowing: Oracle has been known to reclaim idle free instances, and they changed the allowance in 2026 without announcing it. Keep a backup of the data directory somewhere else.

A note on Cloud Run

Cloud Run can run Strata, but only as a demo, and only with care. There is no local disk that survives a restart, so:

  • Set --max-instances=1. This is not optional. Two containers on one checkout will corrupt it.
  • Set STRATA_MODEL_REPO so the container clones the model on every cold start.
  • Seed the administrator, or run with STRATA_AUTH=off and an empty feature list.
  • Accept that stored credentials, the delivery log and the audit log are lost on every cold start.
gcloud run deploy strata \
  --image ghcr.io/rk-chavali/strata \
  --max-instances 1 \
  --min-instances 1 \
  --set-env-vars STRATA_MODEL_REPO=https://github.com/your-org/data-models.git \
  --set-env-vars STRATA_COOKIE_SECURE=true,STRATA_TRUST_PROXY=true

--min-instances 1 costs money but avoids a cold start on every visit, which on Cloud Run means re-cloning the repository.

After you deploy

Four checks, whichever host you picked.

  1. Is setup closed?

    curl -s https://your-host/api/health

    Then sign in as an administrator and open /api/health/detail. If auth.needsSetup is true on a public address, anyone can claim the administrator account. Seed it now.

  2. Are the security headers there?

    curl -sI https://your-host/api/health | grep -i "content-security-policy\|x-frame-options"

    If those are missing, something in front of Strata is stripping them.

  3. Does the data directory survive a restart?

    Restart the service and sign in again. If you are signed out, the volume is not mounted where you think it is, and you will lose everything on the next deploy.

  4. Do live updates work?

    Open the site in two browsers and rename something in one. If the other does not notice within a second or two, a proxy is buffering the event stream. See Behind a proxy.
