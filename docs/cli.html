The command line

The CLI exists mainly for one job: being the gate in your pipeline. Everything else it does is useful, but this is the part that turns Strata from a drawing tool into something that actually holds a standard.

The CI gate

strata check

Validates structure and referential integrity, then lints names against your standards. Returns a non-zero exit code if anything fails, which is what makes a pipeline stop.

Exit codeMeans
0Clean.
1Findings. The pull request should not merge.
2You used the command wrong. A bad flag, a missing workspace.

In GitHub Actions:

.github/workflows/strata-check.yml

name: strata check

on: [pull_request]

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npx @strata/cli check --format github

--format github emits annotations, so findings appear on the changed lines of the pull request instead of in a log nobody opens.

Then require it

Adding the job is half the work. Go to branch protection on main and make this check required. Without that, the job runs, goes red, and the pull request merges anyway.

Commands

CommandWhat it does
strata init [dir] Create a model repository. Writes strata.config.yaml and a .gitattributes.
strata check Validate and lint. The recommended CI gate.
strata validate Structure and referential integrity only. No naming rules.
strata lint Naming standards only.
strata fmt Rewrite every file in canonical form. Add --check to report instead of writing.
strata reorganize Move every file to a different layout.
strata generate ddl Emit CREATE TABLE and policy tag DDL.
strata generate dataform Emit Dataform SQLX from the mappings.
strata generate all Both of the above.
strata info Summarise the workspace. Useful as a first check that Strata can read it at all.
strata mcp Serve the model to an AI agent. Read only, over stdio.

Options that work everywhere

OptionWhat it does
--cwd <path>Run as if you were in this directory.
--format <fmt>pretty, json or github.
--strictTreat warnings as errors.
--versionPrint the version.

Use --format json when you want to do something with the findings yourself, such as posting a summary somewhere or counting them over time.

Changing the file layout

Where a file sits carries no meaning in strata. Every object declares its own kind, id and owning model inside the file, and the loader reads content rather than inferring from paths. So you can reorganise whenever you like and nothing breaks. 

strata reorganize --preset by-layer --dry-run

Always look at the dry run first. Then drop the flag to actually move the files.

PresetGroups files by
flatNothing. Everything in one folder.
by-kindObject kind: tables, entities, relationships.
by-modelWhich model owns it.
by-model-and-kindBoth. This is the default.
by-subject-areaSubject area, such as Sales or Finance.
by-layerWarehouse layer: raw, staging, mart.
single-file-per-modelOne file per model, everything inside it.
customYour own template, such as models/{model}/{layer}/{name}.yaml.

A test asserts that switching between any two presets leaves the semantic content byte for byte identical. Moving files is genuinely just moving files.

Generating output

strata generate ddl --out DDL --codeowners
OptionWhat it does
--out <folder>Where to write. Defaults to DDL.
--model <name>One model only. Defaults to every physical model.
--template <path>Path template, such as {dataset}/{name}.sql.
--or-replaceCREATE OR REPLACE instead of CREATE IF NOT EXISTS.
--codeownersAlso write a CODEOWNERS file from model ownership.
--dry-runShow what would be written.

Output is reproducible. Running it twice on an unchanged model produces byte identical files, so a generated folder committed to the repository does not churn.

Serving the model to an agent

strata mcp --cwd /path/to/your/models

Starts an MCP server over stdio, so an AI agent can query the model directly. An agent asking "what feeds dim_customer.email" gets the answer the lineage panel computes, because it is literally the same function.

To wire it into Claude Code or another MCP client:

{
  "mcpServers": {
    "strata": {
      "command": "npx",
      "args": ["@strata/cli", "mcp", "--cwd", "/path/to/your/models"]
    }
  }
}
Read only, structurally

There is no write tool, no edit path, and nothing imported that could perform one. The whole server depends on the query layer and the loader, neither of which can change a workspace.

That is deliberate. An agent that wants to propose a change should do it the way a person does, as a branch and a pull request somebody reviews, not by writing YAML behind everyone's back.

Generating a password hash

Not part of the CLI, because it belongs to the server. Run it from the image: 

docker run --rm -it ghcr.io/rk-chavali/strata \
  node apps/server/dist/hash-password.js

Or from a source checkout:

node apps/server/dist/hash-password.js

It asks for a password without echoing it, then prints the hash on stdout and the instructions on stderr. So you can pipe the hash somewhere clean: 

node apps/server/dist/hash-password.js > hash.txt

The password is read from stdin rather than taken as an argument, because an argument lands in your shell history and in the process list where any other user on the machine can read it.
