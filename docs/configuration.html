Reference

Configuration

Every option is an environment variable. None are required to start. Anything you supply this way is read only in the UI, so Settings shows it as "set by your deployment" instead of letting somebody create drift that the next upgrade silently reverts.

Where the model lives

VariableDefaultWhat it does
STRATA_WORKSPACE examples/quickstart Path to the git repository holding your models. Mount your checkout here.
STRATA_DATA_DIR .strata-data Accounts, the session signing secret, encrypted credentials, the delivery log and the audit log. Persist this.
STRATA_MODEL_REPO unset Clone this repository on startup when the workspace is empty, meaning the one named here rather than Strata's own. This is what makes a Kubernetes or platform deploy possible, where there is no host folder to mount.
STRATA_MODEL_BRANCH the repo default Which branch to check out.
PORT 4000 The port to listen on.

Accounts and sign in

VariableDefaultWhat it does
STRATA_AUTH on Set to off to disable sign in entirely. Everyone then has every permission.
STRATA_ADMIN_USERNAME unset Create this administrator at boot, if no account exists yet.
STRATA_ADMIN_PASSWORD_HASH unset The scrypt hash of that account's password. Generate one with the hash-password script. Preferred.
STRATA_ADMIN_PASSWORD unset A plain password instead of a hash. Easier to try, worse to store.
STRATA_COOKIE_SECURE false Send the session cookie with the Secure flag. Set to true whenever you serve over HTTPS.
The most common confusing failure

STRATA_COOKIE_SECURE=true on plain HTTP means the browser drops the cookie without any error. Sign in appears to work and you stay signed out. Leave it false for local work, true behind real TLS.

Why seeding the admin matters

First run setup is open until an account exists. It reopens whenever the data directory is empty, which happens if you forget the volume, or set persistence.enabled: false in the Helm chart. Seeding the administrator closes that window completely, because the account is created before the server starts listening.

Seeding only happens when there are no accounts at all, so leaving these variables in place is safe and does nothing on later restarts.

Network and browser security

VariableDefaultWhat it does
STRATA_TRUST_PROXY false Believe the X-Forwarded-For header. Set to true when something sits in front of strata.
STRATA_ALLOWED_ORIGINS empty Comma separated origins allowed to call the API cross-site. Empty means same-origin only, which is right for almost every deployment.
STRATA_CSP_CONNECT_SRC empty Extra values for the content security policy's connect-src. Only needed when the API is on a different origin from the UI.
STRATA_SSRF_ALLOW empty Comma separated hosts that are allowed to resolve to a private or link-local address.

Why outbound requests are restricted

Several URLs come from a form: the webhook target, and the Confluence and Jira site URLs. Strata refuses to send a request to loopback, link-local or private address ranges, because on a cloud instance the interesting target is the metadata endpoint at 169.254.169.254, which hands out the machine's own credentials to anything that can reach it.

If your Jira really is on an internal address, allow it explicitly:

STRATA_SSRF_ALLOW=jira.internal,confluence.internal

Redirects are followed by hand and every hop is checked, so an allowed host cannot bounce the request somewhere the check would have refused.

Why the proxy setting affects security

STRATA_TRUST_PROXY decides what the sign in throttle counts against. Leave it off behind a proxy and every visitor shares one counter, so one person guessing passwords locks out everybody. Turn it on with no proxy in front and a client can claim any address it likes, which defeats the throttle. Set it to match reality.

Turning features off for a deployment

VariableDefaultWhat it does
STRATA_FEATURES unset, meaning everything on A comma separated list of features this deployment permits at all. Valid values: integrations, skills, bigquery.

Three states, and the difference between the last two matters:

ValueResult
Not set at allEverything is on. This is the normal self-hosted behaviour.
STRATA_FEATURES=skillsOnly agent skills. Integrations and BigQuery routes return 404.
STRATA_FEATURES=""Nothing is on. An empty list means an empty list.
This is a deployment decision, not a setting

An admin toggle is a preference inside one instance. This is the operator of the host saying a capability is not available here at all. Nothing inside the app can turn it back on, which is exactly what you want for a public trial where every visitor is effectively an administrator.

A route for a disabled feature returns 404, not 403. A feature that is off for the deployment does not exist here for anyone, and saying so is both more honest and less interesting to somebody poking around.

One workspace per visitor

For a hosted trial. Off unless STRATA_TENANT_DIR is set, and that default matters: a self-hosted instance keeps serving the one workspace its operator mounted.

VariableDefaultWhat it does
STRATA_TENANT_DIR unset Turn on multi-tenant mode. Each visitor gets a directory under this path.
STRATA_TENANT_SEED unset Copy this workspace into every new visitor's directory, so they land on something rather than an empty canvas.
STRATA_TENANT_TTL_MS 7 days Delete a workspace after this long with no writes. Set 0 to never expire.

Visitors are identified by a signed cookie. The identifier is generated by the server and signed, never accepted from the client, so nobody can claim somebody else's workspace by editing a cookie.

Stored credentials, the delivery log, presence and the audit log are all kept per tenant too, not just the model files.

Turn off outbound features in multi-tenant mode

If visitors are anonymous, every one of them is effectively an administrator inside their own workspace. Set STRATA_FEATURES="" so none of them can make your server send a request. Strata prints a warning at startup if you do not.

Credentials

VariableWhat it does
GITHUB_TOKEN Opens pull requests. Without it you still get branch, commit, push and a compare link.
STRATA_GITHUB_TOKEN_FILE Path to a mounted file holding the token. Preferred in production: the value never appears in docker inspect or kubectl describe pod, and it rotates without a restart.
STRATA_SKILLS_API_KEY Model provider key for agent skills. Without it, agent skills report themselves as skipped rather than quietly passing.
STRATA_SKILLS_MODEL Which model agent skills use. Defaults to a current Claude model.
STRATA_GCP_ACCESS_TOKEN A short lived Google token. Good for trying the policy tag sync, not for running it, because it expires in about an hour.
STRATA_GCP_CATALOG_BASE Override the Data Catalog endpoint, for VPC Service Controls or a private endpoint.
STRATA_SECRET_* Override any stored credential from the environment.
GIT_AUTHOR_NAME, GIT_AUTHOR_EMAIL Fallback commit attribution. A signed in user's own name is used when available.

Credentials entered in the UI are encrypted with AES-GCM and stored in the data directory, never in the model repository, and never returned to the browser. You get the last four characters so you can tell which credential is in place, and nothing more.

Logging

VariableDefaultWhat it does
STRATA_LOG_REQUESTS false Log a line for every request. Failures are always logged regardless.
STRATA_DEBUG false Print stack traces in CLI output instead of just the message.
STRATA_VERSION, STRATA_COMMIT unset Reported by /api/health/detail, so a post-deploy check can prove which build is live.

Logs are one JSON object per line on stdout, which is what every container platform collects. Every response carries an x-request-id header, and an unexpected error shows that id to the user. When somebody reports a failure, that id finds the exact log line.

Values under keys that look like secrets, such as anything containing "password", "token" or "key", are replaced with [redacted] before a line is written.

Merge detection

VariableDefaultWhat it does
STRATA_WATCH_INTERVAL_MS 60000 How often the default branch is polled for merges. Set 0 to switch it off.

Worth turning off on a shared instance behind a rate limited enterprise remote. With polling off, integrations still fire on proposals and failed validation. Only the merge event stops.

What lives in the config file instead

Modelling decisions do not belong in environment variables. Lint rules, naming standards, file layout, DDL output and integration settings all live in strata.config.yaml inside your model repository.

That is deliberate. Those are decisions made by data architects and reviewed as pull requests alongside the models they govern. Editing them in the UI writes that file and shows up in Changes, so it still lands as a reviewable commit rather than a live mutation nobody can audit.

Integration credentials are the exception. Non-secret settings, such as which Confluence space to publish to, go in the config file where they are reviewable. The token goes in the encrypted store, because committing it would be exactly the mistake this whole design exists to avoid.
