Introduction

Your data model, in your git repo

Strata is a data modelling tool for BigQuery. It looks like the modelling tools you already know, but it stores the model as plain files in your own git repository. That one decision changes almost everything else about how it works.

The two ideas

1. The model is files in your git repo

Not a database that can export to git. Actual YAML files that you can read, diff, review and revert with the tools you already use every day.

Because of that, a lot of hard features come for free. Version history is git log. Working on two things at once is a branch. Reviewing a change is a pull request. Undoing a bad change is a revert. None of that had to be built, so none of it can drift out of sync with reality.

It also means an edit somebody makes in the UI becomes a pull request that a person reviews, instead of a silent change to a database that nobody can audit later.

2. Standards are enforced in CI, not in the app

Strata ships a command called strata check. You run it in your pipeline. If a change breaks a naming standard or a referential rule, the pull request cannot merge.

This matters more than it sounds. A tool that only enforces rules inside its own window gets bypassed the first time somebody is in a hurry. A gate in the pipeline does not.

The short version

If your team already reviews code in pull requests, Strata lets you review your data model the same way, by the same people, with the same tools.

What Strata does today

Written plainly, so nothing surprises you after you have installed it.

AreaWhat you get
Modelling Three tiers, conceptual to logical to physical, linked together. A diagram canvas you edit directly. A data dictionary covering every field of every object.
Governance Validation rules you can tune. Naming standards with automatic fixes. Classification that flows from a domain down to a column. Column level lineage and impact analysis. Generated CODEOWNERS.
Output BigQuery DDL. Dataform SQLX. ALTER statements that respect what BigQuery will actually accept. A data dictionary as Markdown or a single HTML file. Diagram export to SVG or PNG.
Import erwin XML, DDL scripts, and CSV.
Workflow An edit becomes a branch, a commit and a pull request. History per model and per object. Compare two models and generate the migration between them.
Integrations Webhook, Confluence, Jira and GitHub. Each one fires on events you choose, with a delivery log you can read.
For agents An MCP server so an AI agent can read the model directly and answer questions like "what feeds this column". Read only, by design.

What is not built yet

Named here so you find out now rather than later.

  • No live BigQuery connection. Strata does not read your warehouse, and it cannot reverse engineer a model from one.
  • No drift detection between the model and the real warehouse.
  • No picking and choosing which changes to apply when you compare two models. It is all or nothing today.
  • No single sign on. Local accounts only. If you need SSO, put an authenticating proxy in front of Strata for now.
  • No visual diff of models. You get git's text diff, which is good but not a picture.
No licence key, ever

There is no seat counting, no activation and no phone home. You run the image in your own infrastructure and nothing in it talks to us. Access control is the role model plus whatever your network already enforces.
