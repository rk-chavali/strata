Two decisions shape everything else

Strata looks like the modelling tools you already know. Underneath, two choices make it behave very differently.

One

The model is files in your git repo

Not a database that can export to git. Actual YAML you can read, diff, review and revert with the tools you already use.

So the hard features come for free. History is git log. Two things at once is a branch. Review is a pull request. Undo is a revert. None of it had to be built, so none of it can drift out of step with reality.

Two

Standards are enforced in CI, not in the app

strata check runs in your pipeline. Break a naming standard or a referential rule and the pull request cannot merge.

This matters more than it sounds. A tool that only enforces rules inside its own window gets bypassed the first time somebody is in a hurry. A gate in the pipeline does not.

What you get

Everything listed here is built and tested. What is missing is further down, named plainly.

Three linked tiers

Conceptual to logical to physical, connected, so you can change the warehouse without touching the business definitions above it.

A diagram you edit directly

Rename, retype and rekey on the canvas itself. Positions persist to a file, so the layout is versioned like everything else.

Governance that follows the data

Classification flows from a domain down to a column, and becomes real BigQuery policy tags.

Column level lineage

What feeds this column, and what breaks if it changes. Ranked by whether it breaks, rewrites or merely informs.

Real output

BigQuery DDL, Dataform SQLX, and ALTER statements that respect what BigQuery will actually accept.

Import what you have

erwin XML, DDL scripts and CSV. You do not have to start from nothing.

Rules you write yourself

Skills live in your repo and run before a proposal. A blocking one refuses it, the same way a validation error does.

Readable by agents

An MCP server so an AI agent can answer "what feeds this column" directly. Read only, by construction.

What is not built yet

Said here rather than left for you to discover after installing.

  • No live BigQuery connection. Strata does not read your warehouse, and it cannot reverse engineer a model from one.
  • No drift detection between the model and the real warehouse.
  • No picking and choosing which changes to apply when comparing two models. It is all or nothing today.
  • No single sign on. Local accounts only. Put an authenticating proxy in front if you need SSO.
  • No visual diff of models. You get git's text diff, which is good but not a picture.
